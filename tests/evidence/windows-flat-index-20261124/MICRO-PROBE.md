## What is measured

Exercise the twelve fixed cases in `CASES` order within each visit. The workloads are hit/refund at 1, 32 and 1,024, empty-table ascending and descending fill, a full live miss and backed-off miss, 128 successive one-dead culls with oldest-rate replacement and front insertion, mostly-retaining expiry, a half-keeping retention pass, full expiry, and a summary-producing shutdown. The retained units are behavioral workload operations as labeled. For example, a hit/refund operation consists of both operations and a churn operation includes its whole cull/admission. Empty-table fill is in a warm process and supplies no process-cold or first-seed metric.

Run a nonmonotonic same-PID/distinct-epoch and OUTSIDE oracle for each arm before timing. That oracle checks exact summary order, a removed key's fresh re-admission and retained-key refund/unrefuse. It also checks an actual cull's liveness callback order, exclusion of OUTSIDE from that callback, exact single removal and append, and resulting known-key mapping. Every visit validates known key positions using a separately generated BTreeMap plus the expected insertion order and confirms actual admit/refund round-trip effects on the addressed rate. Use the same synthetic logical clocks, key order, per-case repetitions and known dead/live decisions. Setup, oracle checks and raw reporting sit outside the Instant intervals; timed case effects are consumed with black_box and checked. The current baseline's RandomState TLS may be warm in this shared executable. Neither library import behavior, wall-clock extension-lock contention, seed/init performance nor process startup is an estimand here.

Run one A then B starter visit in block 0, followed by sixteen balanced measured blocks using ABBA, BAAB, BAAB, ABBA four times. Both arms always have two visits per block. Preserve the actual 24 starter case rows and 768 measured case rows. For each measured block and case, subtract the two baseline elapsed sums from the two candidate elapsed sums, then divide by twice the equal operation count. This gives the candidate-minus-baseline average per case operation from that block. Across the 16 block values, compare the ordinary midpoint median and nearest-rank p90 (15th ordered value) with zero. Both must be at most zero in every case. Ties are accepted as screening values. The code reports exact numerator/denominator pairs. Positive in any case stops the current candidate. Missing or invalid samples produce no verdict. Terminal native success only means the driver completed; use the separate COST_SCREEN field for eligibility and independently recompute it from retained rows. No p-value, population noninferiority or general guarantee follows.

Only a pass warrants considering the two same-path default-feature builds. Both must then satisfy the frozen PE/import and compactness gate. A later startup experiment is a separate preregistered protected cohort using the already reviewed short runner if its exact bytes and independent replay can be bound. No previous ineligible reference is a comparator.
